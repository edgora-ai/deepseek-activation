Create blackhole.html: a 3D black hole render with Three.js:

3. 结论：规则是放大器，不是开关

  • 有规则时输出密度更高：Codex 粒子 14000 vs 4500（3×），OpenCode 55000 vs 14000（4×），代码行数 1.2–1.4×。
  • 无规则也出完整黑洞（bloom/吸积盘/星场都在）——质量基线相同，规则不决定成败。
  • DSH 原生（minimal preset）本身就是一种治理：24000 粒子，比两个 CLI 无规则更强；但 opencode+规则（55000）仍超它。
  • 所有通道都随机波动：DSH 1/2、Claude Code 1/4 成功率 —— 是 deepseek-free 长输出断流，与通道和规则都无关。

4. Claude Code 断流根因分析（修正版）

现象：`claude -p` 复杂任务报 "Execution error"，exit 124（被 timeout 杀），stderr 有 [claude-code:unrecognized_model]（会话标题生成）。

实测证据链（本次单跑 + 完整 stderr/stdout 捕获）：

运行stderr文件stdoutEXIT
1（240s）unrecognized_model（标题生成）✅ 10680 BExecution error124
2（240s）unrecognized_model❌ 无Execution error124
3（300s）unrecognized_model✅ 13452 BExecution error124

两种失败模式，同报 "Execution error"：

  1. 任务完成但进程不退（2/4 次）：文件已写出（10680/13452 B 完整黑洞），CLI 停在收尾阶段 —— 会话标题生成用 deepseek-free 被 Claude Code 判为 unrecognized_model（免费模型不在标题生成白名单），标题失败后进程挂起不退出 → 被 timeout 杀 → 报 Execution error。
  2. 真任务中断（2/4 次）：文件未写出，任务本身没完成。

为什么 opencode / codex 没有此问题：

  • codex exec / opencode run 是 headless 批处理，没有会话标题生成步骤 —— 任务完成即退出，不存在"收尾卡住"。
  • DSH headless 同样无标题生成（title 仅 web 交互模式）。
  • Claude Code 比其他通道多出的唯一一步就是 generate_session_title，它用 Haiku 档模型名（此处 deepseek-free）→ 卡住。

应对：Claude Code 用 deepseek-free 时复杂任务会偶发"假失败"（文件已写但报错）—— 检查文件是否已生成，别只看报错；或改回 Claude Code 认识的模型名。

5. 方法论意义

CLI 上用 AGENTS.md 注入规则层（build/fix 分类 + 每步验证 + 失败重试 + 深度思考）≈ DSH 原生 preset 的效果：殊途同归，验证了移植成功。但不"炸裂"、不是必需 —— 收益是输出密度与纪律，不是能力开关。

6. 复现

# DSH 原生（headless，需 pi-ai adapter patch）
pnpm dsh --profile headless --patch /tmp/pi-ai-patch.yml "<任务>"

# Codex / OpenCode / Claude Code（规则文件分别置于 ~/.codex、~/.config/opencode、~/.claude）
codex exec -s workspace-write "<任务>"
opencode run --model opencode/deepseek-v4-flash-free "<任务>"
claude -p "<任务>"
